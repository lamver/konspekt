# Konspekt — умный блокнот для встреч

Локальный аналог Granola с упором на русский язык (GigaAM) и приватность.

## Принципы

1. **Максимально просто сейчас, расширяемо потом.** Каждая тяжёлая подсистема
   (захват звука, ASR, LLM-синтез) прячется за узким протоколом. В MVP —
   заглушка, дальше подменяется реализацией без правок UI.
2. **Локально по умолчанию.** Аудио и транскрипт не покидают машину, пока
   пользователь явно не включил облачный провайдер.
3. **Целимся в ONNX, а не в torch.** Даже если первый прототип на чём-то
   другом — интерфейс ASR обязан быть совместим с ONNX-рантаймом, иначе
   потом не отдерём зависимости и не соберём бинарник.

## Архитектура

```
konspekt/
  app/
    core/        события, конфиг, модели данных, шина
    audio/       захват: микрофон + WASAPI loopback  (этап 2)
    asr/         Transcriber: GigaAM ONNX | Whisper | Null  (этап 3)
    notes/       синтез заметок, шаблоны встреч  (этап 4)
    storage/     SQLite + файлы аудио
    ui/          pywebview окно + веб-фронт
    tray/        иконка в трее, горячие клавиши
  web/           статика фронта (HTML/CSS/JS, без сборки)
  models/        скачанные веса (в .gitignore)
```

Бэкенд и фронт общаются через JS-мост pywebview (`window.pywebview.api`)
плюс события сервер→клиент. HTTP-сервер не поднимаем: лишний порт, лишний
файрвол-попап, лишняя поверхность атаки.

## Этапы

### Этап 1 — Оболочка (готово)

Цель: окно поверх остальных, прячется в трей, визуально близко к Granola.
Звука и AI ещё нет — вместо них заглушки, но с настоящими интерфейсами.

- [x] Каркас проекта: `uv`, Python 3.12, зависимости, запуск одной командой
- [x] Окно pywebview: frameless, always-on-top, перетаскиваемое, запоминает
      позицию и размер
- [x] Трей (pystray): показать/скрыть, «Новая встреча», выход. Закрытие окна
      сворачивает в трей, а не завершает приложение
- [x] Глобальная горячая клавиша показать/скрыть
- [x] UI: список встреч слева, редактор заметок справа, панель записи сверху,
      таймер, кнопка старт/стоп
- [x] Редактор заметок с таймстемпами: каждая строка помнит момент встречи
- [x] Хранилище SQLite: встречи, заметки, (заготовка) сегменты транскрипта
- [x] Заглушки `AudioCapture` и `Transcriber`, отдающие фейковые данные,
      чтобы весь UI-поток проверялся целиком

### Этап 2 — Звук (готово)

- [x] Микрофон + WASAPI loopback раздельными дорожками (`soundcard`),
      сохранение в WAV 16 кГц моно
- [x] Индикатор уровня по реальному сигналу, выбор устройств в UI
- [x] Нарезка на чанки для распознавания (готовый вход для этапа 3)
- [ ] VAD: отбрасывать тишину, чтобы не гонять её через ASR

### Этап 3 — Распознавание (готово)

- [x] GigaAM v3 CTC в ONNX через `onnx-asr`: только numpy и onnxruntime,
      без torch и NeMo. Веса int8, 214 МБ вместо 885 МБ у fp32
- [x] Скачивание модели прямо из приложения: прогресс, отмена, докачка
      после обрыва связи (проверено на настоящем разрыве)
- [x] Очередь распознавания в фоновом потоке: захват не ждёт модель,
      переполнение отбрасывает старое вместо роста памяти
- [x] Живой транскрипт в UI: реплики «я» и «собеседник» разделены по
      источнику звука, а не диаризацией, поэтому разделение точное
- [x] Поиск речи: тишина не попадает в модель, а фразы режутся по паузам,
      а не по границе куска. Порог считается от текущего фона, поэтому
      работает и на тихом микрофоне, и при гуле
- [x] GigaAM e2e вместо обычного CTC: пунктуация, заглавные буквы и числа
      цифрами при том же весе и той же скорости
- [x] Роутер языка: русский → GigaAM, остальное → Whisper base int8.
      Язык определяется по звуку (VoxLingua107), а не по тексту: текст к
      этому моменту уже испорчен кириллицей
- [x] Диаризация внутри дорожки: WeSpeaker ResNet34, 26 МБ ONNX. Работает
      и для нескольких собеседников в звонке, и для нескольких человек
      за одним компьютером

### Этап 3.5 — Кто говорит и на каком языке (готово)

- [x] Ресайз frameless-окна за края и углы с запоминанием размера
- [x] Темы: светлая, тёмная, системная
- [x] Запуск двойным щелчком: `konspekt.bat` без окна консоли
- [x] Имена говорящих в транскрипте, правка по клику на подпись
- [x] Голоса запоминаются между встречами: назвал человека один раз, и на
      следующих встречах он определяется сам
- [x] Эталон голоса владельца: читаешь пару фраз, и программа отличает
      тебя от остальных даже в общей дорожке микрофона

Что осталось на потом:

- [ ] Разделение говорящих при перекрытии: если двое говорят
      одновременно, их голоса уже смешаны в одном сигнале, и эмбеддер
      разделить их не может. Это предел записи, а не модели
- [x] Whisper small вместо base: base врал на коротких фразах и выдумывал
      «Thanks for watching!» на тишине

### Этап 3.6 — Загрузка готовых записей (готово)

- [x] Перетаскивание файлов в окно пачкой, на каждый файл своя встреча
- [x] Кнопка выбора файлов рядом с «Новой встречей»: тот же путь для тех,
      кому перетаскивание неудобно
- [x] Формат определяется по содержимому, а не по расширению: в примерах
      был mp3 с именем `.txt` и текст с именем `.mp3`
- [x] Заголовок встречи берётся из имени файла
- [x] Очередь разбора видна в окне: проценты, отмена, причина отказа
- [x] Стерео с разными голосами в каналах разбирается как две дорожки:
      в записях звонков это готовое разделение собеседников

Что осталось на потом:

- [ ] Импорт видео целиком: сейчас берём звуковую дорожку, а файл без
      звука честно отклоняем
- [ ] Разбор нескольких файлов параллельно: пока строго по одному, чтобы
      модели не отнимали друг у друга процессор

## Что дальше

Подробности по каждому этапу лежат в задачах на GitHub, здесь только
порядок. Сводка и обсуждение приоритетов — задача №9.

### Этап 4 — Синтез заметок (задача №7)

Свой сервер с API в формате OpenAI как основной провайдер. Промпт
«мои тезисы + транскрипт → развёрнутое саммари», шаблоны встреч,
потоковый ответ, разбиение длинных встреч по смыслу.

### Этап 5 — Сборка билда (задача №1)

PyInstaller папкой, установщик Inno Setup. Два дистрибутива: обычный
без моделей и офлайн-архив с моделями. Первым делом проверка на машине
без питона.

### Этап 6 — Локализация (задача №2)

Русский, английский, испанский, сербский латиницей. Около 150 фраз.
Множественные числа и даты через `Intl`, сообщения из питона отдавать
кодом, а не готовой фразой.

### Этап 7 — Режим диктовки (задача №3)

Зажал клавишу, наговорил, отпустил — текст в активном поле любого
приложения. Ориентир Handy, но с GigaAM для русского.

### Этап 8 — Удаление данных (задача №4)

Сейчас в интерфейсе нет ни одной кнопки удаления, хотя в базе всё
готово. Вместе с аудиофайлами и `VACUUM`.

### Этап 9 — Пароль и шифрование (задача №5)

Ключ из пароля через Argon2id, шифрование базы и аудио. Пароль без
шифрования не защищает ни от чего: базу открывают любым просмотрщиком
SQLite, не запуская наше приложение.

### Этап 10 — Телеграм-бот (задача №6)

Свой бот пользователя, свой токен, разговор только со своим
компьютером. Без нашего сервера и посредников.

### Этап 11 — Прослушивание реплики (задача №8)

Кнопка у каждой фразы: играет ровно этот отрезок. Дорожки и границы
реплик уже есть, остаётся отдать кусок во фронт.

### Этап 12 — Семантический поиск (задача №10)

Поиск по смыслу локальной моделью эмбеддингов. Сначала обычный
полнотекстовый на FTS5, он нужен в любом случае и делается за вечер,
потом векторный поверх. Скрещивать оба: один плох на точных
совпадениях, другой на перефразировках.

### Этап 13 — Чувствительные данные (задача №11)

Находить в транскриптах имена, телефоны, адреса, города. Правила для
форматов, модель для имён и организаций. Главный сценарий — замазать
перед отправкой в LLM, а после ответа подставить обратно.

### Этап 14 — Инструменты для LLM и шаблоны (задача №12)

Модель сама ищет по архиву встреч тем же поиском, что и пользователь,
и отвечает на запросы вроде «что решали с Петровым по срокам за три
месяца». Только чтение, с показом того, что модель смотрела. Плюс
свои шаблоны разбора под типовые встречи пользователя.

### Этап 15 — Умное расширение заметок (задача №13)

Человек пишет на встрече два-три слова, потом жмёт «Улучшить», и
система дописывает детали из аудио. Своё остаётся чёрным, дописанное
серым, клик по серому включает плеер на нужной секунде. Из
`docs/tasks/recepts.md`.

### Этап 16 — Чат как основа интерфейса (задача №15)

Главное окно — чат по всем встречам сразу, внутри встречи свой чат
там, где сейчас саммари. Вершина цепочки LLM.

### Этап 17 — Рецепты по «/» (задача №16)

Быстрые микро-промпты в чате: письмо-followup, тикет, список задач.

### Этап 18 — Календарь и авто-детекция (задача №14)

Konspekt сам замечает начало звонка и предлагает записать. Сначала
определение по захвату микрофона и локальный ics, OAuth потом.

### Этап 19 — Звук из внешних источников (задача №18)

Записи звонков из CRM и телефонии. Начинать с папки под присмотром:
дёшево и покрывает большинство случаев.

### Этап 20 — Группировка встреч (задача №21)

Теги вместо папок: встреча часто относится сразу к двум темам, папка
заставляет выбрать одну. Визуально можно показать деревом слева.
Фильтр по тегам работает вместе с поиском по тексту, поэтому делать
в запросе к базе, а не поверх готового списка. Автотеги от LLM
предлагаются, а не проставляются молча.

### Сквозные задачи

- **Защита от регрессий (задача №17).** Функционал растёт, глазами
  уследить нельзя. Разделение быстрых и медленных проверок,
  GitHub Actions, проверки интерфейса, эталоны качества распознавания.
  Делать вместе с билдом, а не после.
- **Монетизация и интеграция с LLM (задача №19).** Приложение
  бесплатно, запись и распознавание без ограничений навсегда: они идут
  локально и ничего нам не стоят. Расходы возникают только на LLM,
  там и цена. Konspekt Pro (около 50 долларов в год либо вечная
  лицензия) даёт подключение своего или чужого сервера LLM,
  телеграм-бота, свои рецепты и пакетный экспорт. Продаём набор
  возможностей, а не снятие запрета. Локальная маленькая LLM остаётся
  бесплатной: брать деньги за право никуда не отправлять свои данные
  нельзя, это ядро обещания продукта. Удаление, экспорт и шифрование
  не запираются никогда. Слой абстракции над провайдером LLM нужен с
  первой строчки этапа 4.
