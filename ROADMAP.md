# Konspekt — умный блокнот для встреч

Локальный аналог Granola с упором на русский язык (GigaAM) и приватность.

## Принципы

1. **Максимально просто сейчас, расширяемо потом.** Каждая тяжёлая подсистема
   (захват звука, ASR, LLM-синтез) прячется за узким протоколом. В MVP —
   заглушка, дальше подменяется реализацией без правок UI.
2. **Локально по умолчанию.** Аудио и транскрипт не покидают машину, пока
   пользователь явно не включил облачный провайдер.
3. **Целимся в ONNX, а не в torch.** Даже если первый прототип на чём-то
   другом — интерфейс ASR обязан быть совместим с ONNX-рантаймом, иначе
   потом не отдерём зависимости и не соберём бинарник.

## Архитектура

```
konspekt/
  app/
    core/        события, конфиг, модели данных, шина
    audio/       захват: микрофон + WASAPI loopback  (этап 2)
    asr/         Transcriber: GigaAM ONNX | Whisper | Null  (этап 3)
    notes/       синтез заметок, шаблоны встреч  (этап 4)
    storage/     SQLite + файлы аудио
    ui/          pywebview окно + веб-фронт
    tray/        иконка в трее, горячие клавиши
  web/           статика фронта (HTML/CSS/JS, без сборки)
  models/        скачанные веса (в .gitignore)
```

Бэкенд и фронт общаются через JS-мост pywebview (`window.pywebview.api`)
плюс события сервер→клиент. HTTP-сервер не поднимаем: лишний порт, лишний
файрвол-попап, лишняя поверхность атаки.

## Этапы

### Этап 1 — Оболочка (готово)

Цель: окно поверх остальных, прячется в трей, визуально близко к Granola.
Звука и AI ещё нет — вместо них заглушки, но с настоящими интерфейсами.

- [x] Каркас проекта: `uv`, Python 3.12, зависимости, запуск одной командой
- [x] Окно pywebview: frameless, always-on-top, перетаскиваемое, запоминает
      позицию и размер
- [x] Трей (pystray): показать/скрыть, «Новая встреча», выход. Закрытие окна
      сворачивает в трей, а не завершает приложение
- [x] Глобальная горячая клавиша показать/скрыть
- [x] UI: список встреч слева, редактор заметок справа, панель записи сверху,
      таймер, кнопка старт/стоп
- [x] Редактор заметок с таймстемпами: каждая строка помнит момент встречи
- [x] Хранилище SQLite: встречи, заметки, (заготовка) сегменты транскрипта
- [x] Заглушки `AudioCapture` и `Transcriber`, отдающие фейковые данные,
      чтобы весь UI-поток проверялся целиком

### Этап 2 — Звук (готово)

- [x] Микрофон + WASAPI loopback раздельными дорожками (`soundcard`),
      сохранение в WAV 16 кГц моно
- [x] Индикатор уровня по реальному сигналу, выбор устройств в UI
- [x] Нарезка на чанки для распознавания (готовый вход для этапа 3)
- [ ] VAD: отбрасывать тишину, чтобы не гонять её через ASR

### Этап 3 — Распознавание (готово)

- [x] GigaAM v3 CTC в ONNX через `onnx-asr`: только numpy и onnxruntime,
      без torch и NeMo. Веса int8, 214 МБ вместо 885 МБ у fp32
- [x] Скачивание модели прямо из приложения: прогресс, отмена, докачка
      после обрыва связи (проверено на настоящем разрыве)
- [x] Очередь распознавания в фоновом потоке: захват не ждёт модель,
      переполнение отбрасывает старое вместо роста памяти
- [x] Живой транскрипт в UI: реплики «я» и «собеседник» разделены по
      источнику звука, а не диаризацией, поэтому разделение точное
- [x] Поиск речи: тишина не попадает в модель, а фразы режутся по паузам,
      а не по границе куска. Порог считается от текущего фона, поэтому
      работает и на тихом микрофоне, и при гуле
- [x] GigaAM e2e вместо обычного CTC: пунктуация, заглавные буквы и числа
      цифрами при том же весе и той же скорости
- [x] Роутер языка: русский → GigaAM, остальное → Whisper base int8.
      Язык определяется по звуку (VoxLingua107), а не по тексту: текст к
      этому моменту уже испорчен кириллицей
- [x] Диаризация внутри дорожки: WeSpeaker ResNet34, 26 МБ ONNX. Работает
      и для нескольких собеседников в звонке, и для нескольких человек
      за одним компьютером

### Этап 3.5 — Кто говорит и на каком языке (готово)

### Этап 22 — Публичная проверка релизов (частично, задача №23)

Konspekt пишет микрофон, слушает системный звук и перехватывает
горячие клавиши: со стороны это поведение шпионской программы, а
сборки PyInstaller и сами по себе ловят ложные срабатывания. Наш
отчёт «мы проверили» не стоит ничего, поэтому доказательства должны
быть внешними: ссылка на отчёт VirusTotal, подпись происхождения от
GitHub (`attest-build-provenance`, проверяется командой
`gh attestation verify`) и `SHA256SUMS`. Ссылку публиковать с любым
результатом: три красных и объяснение вызывают больше доверия, чем
ноль красных без ссылки.

- [x] `SHA256SUMS` считается при сборке и уезжает в релиз
- [x] Как проверить скачанное: инструкция на четырёх языках в публичном
      репозитории
- [ ] Подпись происхождения и VirusTotal: в workflow написаны, но ни
      разу не отработали, потому что 0.4.0 собран на своей машине

**Что мешает прямо сейчас.** GitHub Actions отказывается запускать
задания: «recent account payments have failed or your spending limit
needs to be increased». Лимит обновляется 1 сентября, после этого нужно
проверить, что задания пошли, и провести первый релиз через CI, а не
руками. Пока так, все проверки и сборка идут руками через `run_tests.py`
и `packaging/build.py`.

**Ловушка с окружением.** Проверки запускать только через
`.venv\Scripts\python.exe run_tests.py`. Системный python видит не все
библиотеки, и десяток проверок падает с «нет такого модуля»: выглядит как
поломка кода, а на деле не тот python.

**Ловушка с PowerShell.** `Set-Content -Encoding UTF8` дописывает в начало
файла невидимую метку, и после этого `pyproject.toml` перестаёт читаться,
а вместе с ним падают проверки сборки. Правки в файлы вносить питоном или
редактором, а не через PowerShell.

**Ловушка при выпуске руками.** `gh release create` с файлами в конце
команды может создать релиз без единого файла и не сказать об этом:
страница выглядит нормальной, а скачивать нечего. Поэтому после выпуска
обязательно скачивать релиз обратно и сверять сумму, а не полагаться на
то, что команда завершилась без ошибки. На 0.5.0 это поймали.

Надёжнее выпускать в два шага: сначала `gh release create` без файлов,
потом `gh release upload`. Одной командой загрузка 60 МБ упирается в
таймаут TLS, и релиз молча не создаётся вовсе. На 0.5.5 так и вышло.

`latest.json` обновляется отдельно, иначе автообновление не увидит новую
версию: `python tools/обновить_latest.py "новость для окна"`. За этим
следит `version_test.py`, он краснеет, пока версия не опубликована.

Кроме оплаты для релиза по тегу нужен секрет `RELEASES_TOKEN` — токен с
правом записи только в `lamver/konspekt-releases`. Сейчас в репозитории
нет ни одного секрета, поэтому публикация упадёт даже с работающим CI.
Ключ `VT_API_KEY` необязателен: без него шаг VirusTotal пропускается.

### Этап 23 — Маркетинг и запуск (задача №24)

Позиционирование: на английском «free self-hosted Granola
alternative», на русском о боли напрямую, потому что Granola здесь
почти неизвестна. Маркетинг пишется заново под каждый рынок, а не
переводится. Слово «бесплатно» уточнять сразу: бесплатны запись,
расшифровка и локальные модели, платно подключение чужих провайдеров.
Главное преимущество не приватность, её обещают все, а качество
русского языка через GigaAM: это проверяется ушами за минуту.
Порядок запуска: публичный README, затем 10-20 живых пользователей,
затем Habr, и только потом Reddit с Hacker News. Испанский и
сербский идут после английского: на испанском берём ценой и GDPR,

### Этап 25 — Качество распознавания вживую (задача №26)

Источник: issue lamver/konspekt-releases#2, «Плохо отрабатывает
транскрипция». Разобрано на боевой записи пользователя (170 реплик,
30.08). Две разные жалобы, чинятся по-разному, брать по порядку.

**Находка 1: определитель языка сходит с ума на короткой русской речи.**
Средняя фраза у пользователя — 1.2 с, а VoxLingua надёжно угадывает
язык только от ~2 с. В результате чисто русская встреча размечена 24
языками (`fr`, `pl`, `lt`, `ka`, `jw`, `gu`...), половина фраз ушла в
Whisper и превратилась в кашу: «и в транскрипт» → `și le transcript.`
(чешский), «в транскрипт» → `la transcript.` (гуджарати). Порог
уверенности 0.5 и минимальная длина 1.2 с в `app/asr/langid.py`
подобраны неудачно для реальных коротких реплик.
- [ ] Поднять `MIN_CONFIDENCE` и `MIN_SECONDS` под короткие фразы,
      подтвердить цифры на боевых записях (`_razbor.py`-подобный
      разбор), а не на глаз
- [ ] При сомнении — не гадать, а сразу считать русским: программа
      прежде всего русская, ошибка в его сторону дешевле

**Находка 2: ощущение «сказал — и тишина».** Не иллюзия: сегмент
уходит в окно только когда VAD закроет фразу (0.6 с тишины) и модель
досчитает (GigaAM требует ≥5 с входа, короткие фразы дополняются
нулями). Частичного текста по ходу речи нет вовсе. Индикатор
активности микрофона уже есть, но он не решает жалобу: у пользователя
эффект есть, на его хенди-компьютере с той же связкой GigaAM+Whisper —
нет. Разница в скорости считать, не в UI-индикаторе. Смотреть, почему
кусок 5-7 секунд молотится на его машине дольше, чем должен (модель
на CPU, потоки onnxruntime, разогрев).
- [ ] Замерить настоящее время `_run` → `on_segment` на его железе,
      не гадать
- [ ] Решить, можно ли безопасно сократить путь фраза→текст, не трогая
      точность GigaAM

**Находка 3 (по итогам обсуждения): ручная коррекция языка фразы.**
Защитная сетка на то, что автоматика всё равно иногда промахнётся.
Пользователь кликает на неверно распознанную реплику, указывает
настоящий язык, модель пересчитывает этот кусок. В тот же интерфейсный
узел сразу закладывается кнопка «перевести на другой язык» для той же
фразы — задел на будущее, разговор двуязычный не редкость.
- [ ] UI: клик по реплике → выбор языка из списка → пересчёт через
      уже сохранённый `pcm` куска (нужно решить, храним ли исходный
      звук фразы для пересчёта или только офсеты в файле записи)
- [ ] Задел на перевод реплики — не делать сейчас, но не закрывать
      место в разметке интерфейса

Порядок: находка 1 (правит корень проблемы, дёшево) → находка 3
(сетка на оставшееся, ощутимо приятная) → находка 2 (дороже и
неопределённее, нужен замер на живой машине пользователя).

### Сквозные задачи

- **Защита от регрессий (задача №17).** Функционал растёт, глазами
  уследить нельзя. Разделение быстрых и медленных проверок,
  GitHub Actions, проверки интерфейса, эталоны качества распознавания.
  Делать вместе с билдом, а не после.
- **Монетизация и интеграция с LLM (задача №19).** Решено. Локальная
  LLM бесплатна без ограничений: любая модель, какую тянет машина
  пользователя, класс железа определяем сами и предлагаем подходящую.
  Наш сервер LLM — софт бесплатен, платно только использование
  модели. Чужой провайдер по ключу (OpenAI, OpenRouter и прочие) —
  лицензия, около 50 долларов в год либо вечная. Мы берём деньги не
  за софт, а за уход к чужому провайдеру. Запись, распознавание,
  удаление, экспорт и шифрование бесплатны всегда. Считать локально
  через llama.cpp: один формат GGUF на все классы железа и сервер в
  формате OpenAI, поэтому слой LLM ходит и в локальную модель, и в
  наш сервер одним кодом. Слой абстракции над провайдером нужен с
  первой строчки этапа 4. Подробности в `docs/tasks/local-llm.md` и
  `docs/tasks/local-llm-tiers.md`.
- **Открытость кода и защита лицензии.** Решено. Наш exe
  декомпилируется за 10–15 минут, защиту от реверса не строим: это
  выброшенные дни, а секретов в дистрибутиве нет. Проверка лицензии
  живёт на сервере, в клиенте только запрос и показ ответа. Кто
  способен пересобрать и снять проверку, тот и так бы не заплатил;
  платят за удобство, а не за замок. Настоящая угроза не реверс, а
  чужая сборка под нашим именем, от неё защищает подпись
  происхождения (задача №23). Открытие кода держим как маркетинговый
  ход в рамках задачи №22. Подробности в
  `docs/tasks/openness-and-licensing.md`.
