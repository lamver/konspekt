# Как работает распознавание речи

Путь одного слова от микрофона до транскрипта на экране. Файлы указаны,
чтобы не потерять место при следующей правке.

## 1. Захват звука — `app/audio/capture.py` (`WasapiCapture`)

Два независимых потока WASAPI: микрофон (`me`) и системный звук, то есть
собеседник в звонке (`them`). Каждый поток режет свою дорожку на чанки
фиксированной длины (`audio.chunk_seconds` в настройках, по умолчанию
0.5с) и на каждый чанк вызывает `AppService._on_chunk(track, pcm, offset)`.

Это единственное место, где нельзя тормозить: любая задержка тут — дыра
в записи. Поэтому `_on_chunk` не распознаёт ничего сам, а сразу кладёт
кусок в очередь и возвращается.

## 2. Нарезка на фразы — `app/asr/vad.py` (`SpeechSegmenter`)

Чанки короткие и режут звук произвольно, посередине слова. Прежде чем
отдавать что-либо модели, `TranscriptionQueue.submit` пропускает поток
через `SpeechSegmenter` — свой на каждую дорожку каждого говорящего,
потому что уровень фона у микрофона и системного звука разный.

Как ищет речь: не нейросетью, а энергией сигнала (RMS по кадрам 20мс).
Порог не фиксированный, а считается от нижнего перцентиля последних
5 секунд — это фон, а не среднее, поэтому долгая фраза не «портит»
собственный порог.

Фраза считается законченной после `SILENCE_TAIL = 0.6с` тишины. Если
речь идёт без пауз дольше `MAX_SEGMENT = 8с`, кусок режется принудительно,
но не как попало — разрез ищется по самому тихому месту в окне
`QUIET_SEARCH` перед потолком, чтобы не рвать слово.

Результат — готовые куски `Speech(pcm, offset)`, только они идут дальше.

## 3. Очередь — `app/asr/queue.py` (`TranscriptionQueue`)

Один фоновый поток на всё распознавание (не пул: onnxruntime сам
использует все ядра, параллельные сессии только мешали бы друг другу и
рвали порядок реплик). `submit` кладёт готовые куски речи в
`queue.Queue`, `_run` разбирает их по одному.

Два режима закладки:
- **живая запись** (`block=False`) — очередь не бесконечная
  (`MAX_PENDING`), при переполнении чанк лучше выбросить и сосчитать в
  `dropped`, чем застопорить поток захвата;
- **разбор файла** (`block=True`) — спешить некуда, `put` ждёт места,
  чтобы не потерять ни одной фразы.

### Черновики

Пока человек говорит длинную фразу, каждую секунду (`PEEK_EVERY`)
`_peek` подглядывает у `SpeechSegmenter` ещё не законченный кусок и
кладёт его в очередь отдельной пометкой `draft=True`. Черновик
распознаётся, показывается на экране через `on_draft` и тут же
забывается — в базу, в поиск говорящего и в саммари он не идёт.
Настоящая фраза придёт следом после паузы и заменит черновик целиком.
Если очередь занята реальными фразами (`DRAFT_SKIP_AT`), черновик просто
пропускается: он не ценен, через секунду будет следующий.

## 4. Выбор модели по языку — `app/asr/router.py` (`LanguageRouter`)

Перед распознаванием кусок проходит через определитель языка
(`app/asr/langid.py`). Дальше развилка:

- кириллица (ru, uk, be, bg...) → **GigaAM** (`app/asr/gigaam.py`) —
  быстрая специализированная модель, ~0.2с на фразу;
- всё остальное → **Whisper** (`app/asr/whisper.py`), поднимается лениво
  при первой нерусской фразе, ~11с на фразу на CPU.

Если акустика не уверена (короткая фраза, шум), берём язык предыдущей
фразы того же говорящего (`_last[speaker]`), а если и памяти нет —
язык по умолчанию из настроек (`fallback_lang`). Языковую память нельзя
наследовать бесконечно: `MAX_UNCONFIRMED_INHERIT = 4` фразы подряд без
подтверждения — и трек откатывается на язык по умолчанию, иначе одна
ошибочная детекция сажает всю дорожку в чужой (и медленный) язык до
конца встречи.

После распознавания текст ещё раз сверяется сам с собой
(`_recheck_by_text`): если Whisper вернул явно кириллический текст —
акустика ошиблась, язык и память дорожки правятся немедленно. Обратной
проверки нет: GigaAM физически не выдаёт латиницу.

Кириллические соседи русского (uk, be, bg) в интерфейсе всё равно
подписываются как «ru» — распознавала-то их русская модель, ставить
ярлык языка, которого нет в тексте, значит врать пользователю.

## 5. Кто говорит — `app/asr/embedder.py`, `app/asr/voices.py`

После распознавания (`TranscriptionQueue._identify`) для настоящих (не
черновых) фраз считается голосовой отпечаток и сверяется с уже
известными голосами встречи (`VoiceRoster.assign`). Отпечаток режет
поток или блокирует что-либо в захвате — весь этот шаг стоит уже после
модели, в фоновом потоке очереди. Ошибка здесь не должна стоить текста:
при любом сбое сегмент всё равно сохраняется, просто без имени
говорящего.

## 6. Готовый сегмент — `app/core/service.py`

- `_on_draft` — черновик, только `bus.emit(TRANSCRIPT_DRAFT, ...)` на
  экран, мимо базы;
- `_on_segment` — настоящая фраза: `store.add_segment` в базу и
  `bus.emit(TRANSCRIPT_SEGMENT, ...)` во фронт. Отсюда сегмент уже
  доступен поиску и саммари.

## Схема целиком

```
WASAPI (мик + системный звук)
        │  чанки по chunk_seconds
        ▼
AppService._on_chunk  ──────────────────────────────────►  asr_queue.submit
        │                                                        │
        │                                          SpeechSegmenter (свой на трек)
        │                                          копит энергию, режет по тишине
        │                                                        │
        │                              ┌─────────────────────────┴───┐
        │                       готовая фраза                  черновик (peek)
        │                              ▼                              ▼
        │                     TranscriptionQueue._run          on_draft → экран
        │                              │
        │                      LanguageRouter._decide (акустика + текст)
        │                              │
        │                    кириллица?──да──► GigaAM
        │                       нет           Whisper (ленивая загрузка)
        │                              │
        │                     _identify (голос → говорящий)
        │                              │
        └───────────────────►  service._on_segment ──► база + фронт
```

## Почему именно так, коротко

- VAD энергией, а не нейросетью — Silero весит немного, но это лишняя
  модель на загрузку и память ради задачи, которую решает арифметика.
- Один поток очереди, а не пул — параллельные сессии onnxruntime рвут
  порядок реплик и делят процессор между собой без пользы.
- Черновики отдельным типом задачи, а не отдельной очередью — им нельзя
  вставать перед настоящими фразами, а `draft=True` в той же очереди
  это гарантирует без лишней синхронизации.
- Языковая память с потолком наследования — без него одна акустическая
  ошибка (шум, короткая фраза) сажает дорожку в чужой и заведомо более
  медленный движок до конца встречи.
