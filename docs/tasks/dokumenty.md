# Этап 20. Документы: PDF, Word и сканы рядом со встречами

## Зачем

Konspekt уже умеет главное для приватного ИИ на своём компьютере:
локальная модель через llama.cpp в установщике, русский в основе,
импорт файлов с очередью, полнотекстовый поиск и вопросы по встрече.
Не хватает одного: работать не только со звуком, но и с документами.

Для бизнеса это отдельный продукт: «ИИ по вашим документам, данные не
покидают компьютер». В РФ довод сильный из-за 152-ФЗ, в ЕС из-за GDPR.
Ориентир HilbertRaum (github.com/HilbertraumAI/HilbertRaum, GPL-3.0):
у них то же самое, но без русского и без встреч. Код оттуда не берём,
лицензии несовместимы. Идеи, замеры моделей и перечень сценариев брать
можно.

## Проба локальных моделей на русском документе

28.09.2026, Ollama на машине разработчика (i9-13900K, 64 ГБ, RTX 3080 Ti
12 ГБ, из них 8,4 ГБ заняты другим). Счёт на оплату, задача вытащить 9
полей в JSON: номер, дата, поставщик, ИНН, покупатель, сумма, НДС, срок
оплаты, пени.

| Модель | Время | Результат |
|---|---:|---|
| gemma3:4b | 6 с | 9 из 9, даты привела к ГГГГ-ММ-ДД |
| qwen3:8b | 28 с | 9 из 9 |
| gemma3:12b | 54 с | 9 из 9 |

Время больших включает загрузку весов в память. Документ чистый, текстом,
не скан. Вывод: для извлечения полей хватает модели на 4B, агент не
нужен. Штатная Qwen3 1.7B не проверялась, это первый вопрос этапа.

## Что сделать

### 1. Импорт документов

- [ ] Тот же путь, что для аудио: перетаскивание в окно и кнопка выбора
      файлов. Формат по содержимому, а не по расширению, как уже сделано
      для звука
- [ ] PDF с текстовым слоем, DOCX, TXT, RTF. XLSX потом
- [ ] Документ хранится как отдельная сущность, не как встреча: у него
      страницы, а не реплики и время. Своя таблица `documents` и
      `document_chunks` с номером страницы
- [ ] Текст попадает в тот же FTS5, поиск находит и в расшифровках, и в
      документах, находка открывает нужную страницу

### 2. Сканы и фото

- [ ] Определять, что у PDF нет текстового слоя, и честно говорить об этом
- [ ] OCR с русским. Кандидаты: Tesseract с `rus` (около 15-20 МБ данных),
      модели PaddleOCR в ONNX (совместимо с принципом «ONNX, а не torch»).
      Выбрать по качеству на настоящих российских сканах, а не по описанию
- [ ] Веса OCR приезжают по требованию, как GigaAM и LLM

### 3. Вопросы по документу

- [ ] Чат по документу так же, как по встрече, ответ потоком
- [ ] Ответ со ссылкой на страницу. Без ссылки бизнесу нельзя проверить
      ответ, а непроверяемый ответ бизнесу не нужен
- [ ] Длинный документ не влезает в контекст: разбиение по смыслу уже есть
      для встреч (`llm/chunking.py`), переиспользовать
- [ ] Честный отказ: если ответа в документе нет, так и сказать, а не
      додумывать

### 4. Шаблоны под российские документы

Как шаблоны встреч, только на вход документ, на выход поля или выжимка.

- [ ] Счёт на оплату: поля в таблицу, проверка суммы и НДС арифметикой, а
      не моделью
- [ ] УПД и акт
- [ ] Договор: стороны, предмет, суммы, сроки, штрафы, как расторгнуть
- [ ] Выписка банка: приходы и расходы по контрагентам
- [ ] Поиск персональных данных перед отправкой наружу. Пересекается с
      этапом 13 (#11), делать одним механизмом

### 5. Модель

- [ ] Проверить штатную Qwen3 1.7B на тех же документах. Если не тянет,
      предлагать модель крупнее по объёму памяти, как в HilbertRaum:
      замер машины и рекомендация
- [ ] Сверка чисел кодом: сумма строк счёта против «Итого», НДС против
      ставки. Модель ошибается в арифметике, код нет

## Проверка готовности

- Счёт, договор, УПД и скан счёта из настоящей работы (без чужих
  персональных данных в репозитории): поля верны, ссылки на страницы
  ведут куда нужно
- Вопрос, ответа на который в документе нет: модель отказывается
- Документ на 50+ страниц не роняет чат и не выходит за контекст
- Всё работает без сети после того, как веса скачаны

## Не делаем

- Агентный режим с вызовом инструментов: маленькие локальные модели в
  нём путаются. Для документов он не нужен
- Облако по умолчанию: только если человек сам указал свой сервер, как
  сейчас для заметок
